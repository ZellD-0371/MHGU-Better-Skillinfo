# Skill-Simulator ↔ Better-Skillinfo 연동 사양 v2 (초안)

- 상태: v2 양쪽 구현됨. **v3(§7)**: Better-Skillinfo 쪽 구현 완료 (2026-11-19, v1.1.0 빌드), Skill-Simulator 쪽 쓰기는 미구현.
- 원칙: **Skill-Simulator는 사실만 쓰고, Better-Skillinfo가 무엇을·어디에 표시할지 정한다.**
  - Skill-Simulator: 현재 화면, 커서가 있는 칸, 커서가 가리키는 대상, 칸들의 화면 사각형.
  - Better-Skillinfo: 아래 "규칙표"로 표시 내용과 위치를 결정. 블록에는 절대 쓰지 않는다(읽기 전용).
- v1(`MHGU-SKSIM-WIN01`, version 1)의 앞 44바이트는 그대로 유지하고 뒤에 필드를 붙인다. version만 2로 올린다.
  v2 블록을 v1만 아는 Better-Skillinfo(v1.1.0)는 버전 불일치로 무시한다(기존 동작).

---

## 3. 대상 (subject)

모든 ID는 **게임 자체 ID**를 쓴다 (Better-Skillinfo의 `armor-skills.bin` = `tools/MHGU-Save-editor/data/armor-skills.csv`와 같은 체계).
DB(`mhxx_all_tables.json`) 내부 번호를 쓰는 경우 반드시 변환해서 넣는다. (Wishlist 스킬 ID가 1 어긋났던 전례 있음)

| subject | 대상 | a | b | points |
|---|---|---|---|---|
| 0 | 없음 | 0 | 0 | 0쌍 |
| 1 | 스킬 계통 | 스킬 계통 ID | 0 | 0쌍 |
| 2 | 방어구 한 부위 | 방어구 시리즈 ID | 부위 1~5 (머리·몸통·팔·허리·다리) | 장식주를 넣은 경우 그 장식주 포인트만 (방어구 자체 포인트는 Better-Skillinfo가 a/b로 계산) |
| 3 | 호석 | 호석 슬롯 수 | 0 | 호석 스킬 최대 2쌍 |
| 4 | 세트 합계 | 0 | 0 | 무기 슬롯 장식주·호석·방어구·장식주 모두 합친 최종 포인트 (0인 계통은 빼도 됨) |
| 5 | 장식주 | 장식주 아이템 ID | 0 | 0쌍 |

검증용 값 (게임 ID 확인):
- 시리즈 33(Vespoid), 부위 2(몸통) → 계통 42 +2 / 부위 3(팔) → 계통 42 +3 (Better-Skillinfo `armor-skills.bin` 기준 실측값).

## 4. Better-Skillinfo 규칙표 (확정)

권장 사용 형태: Skill-Simulator **크기 0.8 + 오른쪽 고정**, Better-Skillinfo 패널은 창 왼쪽 빈 띠.

### 4.1 무엇을 보여주나 — 커서 대상(subject)만 보고 정한다

| 조건 | 표시 |
|---|---|
| screen = 0(없음) 또는 7(모달) | 숨김 |
| area = 2(메인 – 검색 조건) | 숨김 |
| subject 1 스킬 | 그 스킬의 **모든 발동 단계(+/−)와 효과 설명** (포인트 표기 없음, "전체 표시" 설정과 무관) |
| subject 2 방어구 | 그 부위 스킬 포인트(Better-Skillinfo 데이터) + `points`(넣은 장식주) 합산, 효과 |
| subject 3 호석 | `points` 스킬 포인트, 효과 |
| subject 4 세트 합계 | `points` 최종 포인트, 효과 |
| subject 5 장식주 | 그 장식주 스킬 포인트, 효과 |
| subject 0, 또는 포인트가 하나도 없음 | 숨김 |

화면별로 기대하는 subject (Skill-Simulator가 쓸 값):

| 화면 / 커서 | subject |
|---|---|
| 메인 – 목표 스킬 | 1 (그 목표 스킬) |
| 메인 – 검색 조건 | 0 |
| 메인 – 고정할 장비 | 2 / 3, "고정 안 함"이면 0 |
| 스킬 선택 | 1 |
| 결과·저장 – 세트 목록 | 4 (그 세트 합계) |
| 결과·저장 – 세트 상세 | 2 / 3 (그 부위), 무기 줄 등은 4 (세트 합계) 또는 0 |
| 제외 관리 | 2 |
| 장비 상자 | 2 / 3 |

- Skill-Simulator 창(v2)이 열려 있는 동안에는 **게임 화면용 패널(대장간 등)은 숨긴다** (창이 그 화면을 덮으므로).
- Wishlist 창이 열려 있으면 Wishlist 연동이 우선.
- v1 블록(창 사각형만)일 때는 v1.1.0 동작: 게임 화면용 패널을 창 왼쪽 띠로 옮기기만 한다.

### 4.2 어디에 그리나

1. 자동 맞춤(기본): 창 왼쪽 빈 띠. x = 8, 폭 = 창 왼쪽 − 16 (최대 500), y = 창 top, 최대 높이 = 창 높이 (1280 기준 값 × 화면 배율).
2. 띠 폭이 160보다 좁으면: Skill-Simulator 대상일 때만 **커서 옆 칸** 안쪽(여백 8)에 그린다.
   목표 스킬 ↔ 고정할 장비, 세트 목록 ↔ 세트 상세. 전체 폭 목록(스킬 선택·장비 상자·제외 관리)은 덮을 칸이 없으므로 숨김.
   게임 화면용 패널(v1)은 평소 배치.
3. 자동 맞춤을 끄면 설정의 x / y / 폭 / 최대 높이.
4. 글자 크기는 항상 "Skill-Simulator 열림 배치"의 글자 크기.

## 5. 남은 사항

- 장식주(subject 5)는 지금 쓰는 화면이 없으면 번호만 예약.
- 목표 포인트 강조(예: "목표 +10")는 보류. 필요해지면 subject 1의 b에 목표 포인트를 넣고 표시를 추가한다.

## 6. 구현 분담

- Skill-Simulator: §1~3 블록 쓰기 (version 2). 쓰기만 하고 Better-Skillinfo를 호출하지 않는다.
- Better-Skillinfo: v2 읽기, §4 규칙, 헤드리스 테스트(블록 파싱·번호표·규칙 선택·칸 배치) — 구현됨 (`src/sksim_model.rs`, `src/sksim_view.rs`). v1 블록도 계속 지원.

## 7. 버전 3 (v2 레이아웃 + 끝에 4바이트, **328바이트**)

version 필드에 **3**을 쓴다. +0~+323은 v2와 같고, 끝에 필드 하나를 붙인다.

| 오프셋 | 형식 | 이름 | 내용 |
|---|---|---|---|
| +324 | u32 | page | 상세 칸 페이지: 0 = 상세 칸 없음, 1 = 스킬·능력치 페이지, 2 = 생산 소재 페이지 |

 Better-Skillinfo는 1·2·3을 모두 읽고, 2일 때는 위 §3·§4 그대로 동작한다.

### 7.1 바뀐 대상 값

| subject | 대상 | a | b | points (v3) |
|---|---|---|---|---|
| 1 | 스킬 계통 | 스킬 계통 ID | **단계 포인트(i32, 0 = 전체)** | 0쌍 |
| 2 | 방어구 한 부위 | 시리즈 ID | 부위 1~5 | **방어구 자체 스킬(Skill-Simulator 화면 순서) → 넣은 장식주 포인트** 순. 같은 계통은 한 쌍으로 합산. Better-Skillinfo는 자체 계산을 하지 않는다 |
| 3 | 호석 | 슬롯 수 | 0 | **호석 스킬 → 넣은 장식주 포인트** 순 |
| 4 | 세트 합계 | 0 | 0 | **발동 스킬(화면 "발동 스킬" 순서)의 계통 → 나머지 계통** 순 |
| 6 | **무기 슬롯 (신규)** | 0 | 0 | 무기 슬롯에 넣은 장식주 포인트. 없으면 0쌍 |

화면별 변경:
- 결과·저장 – 세트 상세의 **무기 줄 → 6** (장식주 없으면 count 0 → 패널 숨김).
- **추가 스킬 창**(이 세트에 더 띄울 수 있는 스킬): screen 7, area 0, subject 1, a = 커서 줄의 스킬 계통 ID, b = 그 단계 포인트 (예: "광역화+1 / 광역 10" → 광역 계통, b = 10).
- 그 밖의 모달: 지금처럼 screen 7, subject 0.
